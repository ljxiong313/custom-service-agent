# Agent 工具（Tool）规划

> 回答「是否需要加 tool、加哪些」的判断结论。原则：**工具 = Agent 与外部世界的确定性接口**，
> 能用检索/数据库解决的不造工具，能用一个工具覆盖语义的不拆多个。

## 判断结论

需要引入工具调用。纯 prompt + RAG 无法满足：①价格/库存必须精确（向量检索会给出错误数字）；
②转人工是副作用动作必须显式触发；③MCP 工具本身就是动态工具集。
采用 LangChain tool-calling（ChatOpenAI.bind_tools），P0 暂不挂工具（知识库未建立，
挂空工具反而诱发幻觉）。

## 工具清单（按阶段启用）

| 工具 | 阶段 | 类型 | 说明 | 数据来源 |
|---|---|---|---|---|
| `rag_search` | P1 | 只读检索 | 商品说明/政策类开放问题的语义检索，返回带引用(top-k) | Chroma + BM25 混合检索 + rerank |
| `query_product` | P1 | 只读查表 | 价格/库存/SKU 精确查询，支持名称模糊匹配与规格过滤 | product 结构化表（Excel 导入） |
| `recall_memory` | P2 | 只读检索 | 召回当前用户的长期偏好画像（预算、历史咨询结论） | 长期记忆 Chroma collection |
| `request_handoff` | P3 | **副作用** | 创建转人工工单并推送企微卡片；参数含原因摘要、紧急度 | handoff_ticket 表 + wecom client |
| MCP 动态工具 | P4 | 混合 | 外部 MCP Server 注册的工具（示例：订单查询、物流查询） | 各 MCP Server |
| `web_search`（可选） | P4+ | 只读检索 | 通用知识兜底（行业百科类问题），仅在配置了搜索 key 时注册 | Tavity/必应等 |

## 不做的工具（避免过度设计）

- ~~`send_message`~~：会话消息由前端 SSE 链路负责，Agent 不应直接发消息。
- ~~`update_memory`~~：中期摘要与长期画像由后台管道（对话结束后异步抽取）写入，
  不适合让模型在对话中随手改记忆。
- ~~`faq_lookup`~~：与 `rag_search` 职责重叠，FAQ 作为知识库的一种文档类型进 RAG 即可。

## 设计约束

1. 副作用工具（`request_handoff`、MCP 写操作）必须走**执行确认**流程（P3/P4 实现确认卡片）。
2. 每个工具 docstring 面向 LLM 写作：何时用、参数语义、返回结构；中文描述。
3. 工具注册集中在 `app/core/agents/tools/`（P1 创建），按阶段渐进 bind 到模型，
   persona prompt 同步声明工具可用范围。
4. 工具失败返回结构化错误字符串（模型可复述给用户），不抛异常中断对话流。

## 实施现状（P6 收尾时更新）

`rag_search`、`query_product`、`recall_memory`、`request_handoff` 与 MCP 动态工具均已实现并注册
（`app/core/agents/tools/__init__.py` 按知识库就绪状态与用户画像存在与否动态装配）；
`web_search` 保持未启用（可选增强，未接搜索 key）。
副作用确认链路：`request_handoff` 无需确认直接执行（用户显式意图），MCP 服务器级
`require_confirm` 开启时挂进进程内确认表等待裁决（180s 超时默认拒绝）。
**入口有两个**：SSE 客户端会收到 `confirm_request` 事件（协议保留，供评测/集成脚本），
而 P8 起的界面没有 SSE 消费方，所以实际由 MCP 页轮询 `GET /api/v1/mcp/pending` 列出
待确认卡片、`POST /api/v1/mcp/confirm` 回传裁决——**任何渠道**（平台买家、SSE 会话）
的排队都在这里由人代点。注意 `/pending` 对所有登录用户可见且带完整工具入参，
这是演示形态的放开，收紧口径见 docs/待办与风险.md。

**P8 变更**：转人工改为**两步确认制**——`request_handoff` 只允许在客户对话中明确同意后调用
（persona 与工具 docstring 同步约束）；关键词触发不再直接建单，而是进入 `awaiting_confirm`
状态由 runner 询问买家、按肯定/否定回复裁决。运营台（/chat）人工代答不经工具，
直接走 `POST /api/v1/console/conversations/{id}/reply`。
