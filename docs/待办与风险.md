## 一、已修（B3 生产化批次）

### 部署与运行约束

| 原问题 | 现在的处置 |
|---|---|
| 只能单进程：MCP 确认表是进程内 `asyncio.Future` | 确认请求改成落库状态机 `toolconfirmrequest`（pending → approved/rejected/expired），等待方轮询读库、任何进程都能裁决，并记录 `decided_by/decided_at` 形成审计。见 `app/services/mcp/confirm.py` |
| 只能单进程：sweeper 每进程各扫一遍 | 新增 `workerlease` 租约表（`app/services/lease.py`），`session_sweeper` / `memory_backfill_loop` / `outbox_retry_loop` 都先抢约（TTL 90~180s）再干活；会话级的条件 UPDATE 抢行保留，所以即使租约抖动出现两个持约者，也不会重复提示或重复结单 |
| 记忆管道重启即丢 | 任务落库 `memoryjob`：同会话靠 `INSERT ... WHERE NOT EXISTS` 原子去重，执行前 `queued→running` 抢行，启动时 `recover_memory_jobs()` 收回中断项，后台循环补跑。见 `app/services/memory/pipeline.py` |
| Docker 产物未验证 | Dockerfile 改两阶段（node 打 dist → python 运行），compose 把密钥改成环境变量必填（缺 `CS_JWT_SECRET` 直接拒绝启动）。**验证交给 CI 的 `docker` job**（build + 起容器 + `/ready` + 冒烟打容器）；本机仍没有 docker，我没有亲手跑过 build |
| 备份脚本只覆盖 SQLite | `scripts/backup_data.py` 支持 SQLite（backup API）/ MySQL（`mysqldump --single-transaction`）/ PostgreSQL（`pg_dump`），口令不进命令行（MySQL 走 0600 defaults 文件、PG 走只注入子进程的 `PGPASSWORD`）；每份快照写 `manifest.json` |
| 恢复流程没演练过 | 新增 `scripts/restore_data.py`（先校验清单再动手；原数据挪进 `data/.restore-pre-*` 不删除；外部库只打印命令不代做灌库；配置文件不自动覆盖）与 `scripts/verify_restore.py`（恢复后对账 Chunk 表 ↔ Chroma 向量，`--fix` 按文件补建）。链路有单测 `tests/test_backup_restore.py`，含"直接 cp 的残缺 WAL 主文件必须被判死" |
| 不用 Alembic | 引入 Alembic：`alembic.ini` + `migrations/` + 覆盖全部现有表的 0001 baseline；`database.migrate_mode` = `auto`（旧行为，开发用）/ `alembic`（生产：启动跑 `upgrade head` 且**不再** `create_all`，漏写迁移会启动失败而不是被悄悄补列）。`tests/test_migrations.py` 断言 baseline 建出的表集合与 metadata 一致、autogenerate 无残留 diff |

| RBAC 只有 admin/user 两档 | 三档 admin / **staff（客服）** / user：跨用户会话只读+代答、工单看板、外发箱、MCP 确认、用量与告警只对 staff+ 开放，普通用户退化为只看自己的会话。顺带修掉一个真 bug：`PATCH /auth/users/{id}/role` 的"最后一个管理员"保护原先写成 `if body.role != 'admin'`，导致**给普通账号提权成客服**也会被 409 拦住，客服根本招不进来 |

### 可观测性、可靠性与性能

- **计量**：新表 `llmcall` 记录每次外呼的 kind/provider/model/token/耗时/成本估算/成功失败；
  六个入口全接（runner 每一轮对话、中期摘要、长期画像、embedding、rerank、视觉解析）。
  模型上报值与本地估算值用 `estimated` 区分；没配 `llm.pricing` 时成本是 `null` 而不是 0 元。
- **容错**：`llm.fallback` 备用 provider 链——失败且**还没吐出第一个字**时才换环重跑
  （已经流出去的字收不回来，换模型重跑会让买家看到自相矛盾的回答）。
- **限流**：`app/utils/rate_limit.py` 令牌桶，只作用于写路径与外部回调；登录/注册单独收紧
  防爆破；429 带 `Retry-After`。
- **探针**：`/health` 存活；`/ready` 就绪（库可查 + 迁移 + 无致命安全项；模型没配只算
  降级不算死，否则知识库/工单这些不依赖模型的功能会被一起摘掉）；`/metrics` Prometheus
  文本端点（配 token 才开放，生产没配 token 直接 403）。
- **告警面**：`GET /api/v1/system/alerts` 汇总安全缺配、24h 模型错误率、外发失败/死信、
  知识库与记忆任务积压、卡住超过 60s 的确认卡片；`GET /api/v1/system/usage` 给用量汇总。
- **运营看板**：`GET /api/v1/insights/dashboard` + 前端「运营看板」页（机器人独立解决率、
  转人工率、平均轮次与关闭率、首响/处理/会话时长与中位数、渠道分布、模型用量与成本）。
  口径集中写在 `app/api/v1/insights.py` 的模块注释里，页面不重算，避免两套数字打架
  （已经用 `test_alert_and_usage_agree_on_failure_count` 钉住两边一致）。
- **BM25 持久化**：`app/services/rag/bm25_store.py`，`rag.bm25_persist` 默认开；语料版本标记
  判失效、原子写、进程内锁，缓存文件损坏时降级重建而不是让检索崩。实测脚本
  `scripts/bench_rag.py`（1k/10k/50k 切片的首次与命中延迟）。
- **入库吞吐**：`rag.embedding_batch_size` 可配（上限 20，超了夹紧并告警）；失败批次重试后
  仍失败才落 `KnowledgeFile.error` 并显式标注"向量化失败"，不再静默只留 BM25。
- **出站可靠性**：`OutboxRecord` 加 `attempts/next_retry_at/last_error`，
  `app/services/platforms/outbound_retry.py` 指数退避重投（最多 4 次后进死信：仍为 failed
  但不再重投），重投循环走租约选主；`readiness` 会点名还缺的出站项。
- **附件可达**：平台外发的 `[附件]` 链接改为「公网绝对地址 + 签名」；没配
  `server.public_base_url` 且是真实外发时，改成可读提示而不是发一条点不开的相对路径，
  并在 `readiness` 与启动自检里点名（生产缺它属 fatal）。
- **平台参数核对**：`readiness` 的每个 ★ 字段加 `needs_review`，设置页显式标"需要人工核对"，
  把"哪些字段是照记忆写的"变成页面上一眼可见的清单。
- **满意度回访**：结单时（`session.rate_survey_enabled` 开启后）在告别语后附一条**带 HMAC 签名**
  的评价链接（`/api/feedback?conv=&exp=&sig=`，默认 7 天有效）。这是全项目唯一的免登录写入口，
  所以边界都钉住了：签名绑定单个会话、过期即失效、`sessionrating.conversation_id` 唯一 →
  一会话只记第一票（重复提交 409，不覆盖）。回访页是无 JS 的纯表单（平台内置浏览器也能开），
  参数不进 HTML 明文。看板新增 `satisfaction` 块（均分、参评率、1-5 分布）。
- **企微实现可测化**：签名/加解密抽成纯函数（`app/services/wecom/crypto.py` 的
  `signature` / `verify_signature` / `pack_plain` / `unpack_plain` / `encrypt_b64` /
  `decrypt_b64` / `extract_encrypt`），补了错签名、时间戳不符、CorpID 不匹配、密文不合法、
  URL 验签往返等边界用例。

## 二、仍然存在的边界（这才是待办）

### 需要外部条件才能推进

1. **四平台真实出站仍未与官方联调**。参数是可配置骨架，`reply_method`/`media_method` 等
   ★ 项要靠 `docs/平台接入.md` 人工核对（页面已列出 `needs_review` 清单）。没有资质时
   只能保证：mock 全链路可演示、真实模式缺参数报可读错误。
2. **企微真实回路只做到"口径可单测"**。新增用例是**实现自洽向量**（自己签自己验），
   不是与企微服务器联调的结论——别把绿测当成"企微已经通了"。
3. **Docker 镜像由 CI 验证**：本机没有 docker，我没有亲手跑过 `docker build`/`compose up`。

### 有意没做（做了反而自欺）

4. **没有多租户**。RBAC 是三档角色 + 会话归属过滤，但知识库、商品表、MCP 配置、Agent 人设
   仍是**全局共享**。一个实例服务多个互不信任的商家需要租户表与全链路 scoping，
   现在靠部署多套隔离。这是产品化上最实质的缺口。
5. **满意度与质检没做**。看板能算解决率与时长，但"客户满不满意"没有采集入口、没有落库、
   没有报表。结单回访会往买家侧主动发消息，属于对外话术变更，要业务方定稿再实现。
6. **凭据仍存 localStorage（前端 token）**。签名媒体 URL 解决了"拿到 URL 就能读"，
   但 XSS 一旦发生，localStorage 里的 token 会被读走——要彻底解决需要 HttpOnly cookie +
   CSRF 防护，属于鉴权模型改造，没在本批次范围内。
7. **限流与部分缓存是进程内的**。令牌桶、HTTP 计数、BM25 缓存、MCP 工具缓存每进程一份：
   多副本时限流阈值要按副本数折算，`/metrics` 的 `cs_http_*` 要抓取端聚合。
   真正的分布式限流应该放到网关层。
8. **运营台仍靠轮询**（会话列表 4s、设置页告警 30s）。后端保留了 SSE 事件协议，
   但前端没有长连接消费方。在线会话数上去后这是第一个要换的东西。
9. **Agent 人设是"实例级"可配置，不是"店铺级"**。`agent` 配置节能改名字/语气/字数上限/
   转人工触发词与话术（`app/core/agents/persona.py`，runner 的状态机读同一份配置，
   `tests/test_persona_config.py` 有集成用例），但要按店铺给不同人设，得等人设进库——
   与第 4 条的租户模型一起做才有意义。
10. **Alembic 只有 0001 baseline**。它证明了 autogenerate 与当前 models 无 diff，
    但此后新增的列仍同时靠 `db/migrate.py` 的 `ADDITIVE_COLUMNS` 幂等补列。
    两套机制并存是过渡态；收敛方向是生产只用 `migrate_mode=alembic`，开发期才允许 `auto`。
11. **SQLite 单写者没变**。请求线程、sweeper、入库 worker 三方并发写靠 WAL +
    `busy_timeout=5000` 扛，高并发下写入排队会变成可感知延迟。多副本请换 Postgres
    （租约与队列已经为此准备好；`requirements.txt` 里仍没有 pymysql/psycopg，要自己补）。

### 测试与无障碍的残留缺口

12. 带真模型的评测需要 CI secret（`vars.HAS_MODEL_KEY` + `secrets.DASHSCOPE_API_KEY`），
    **目前还没配**，所以流水线里对话质量断言仍是 SKIP 状态。
13. 前端没有屏幕阅读器逐屏朗读验证，也没有 <400px 真机窄屏实测。
14. SQLite ↔ Chroma 对账脚本有了（`verify_restore.py`），但**还没接到页面按钮**，
    目前只能命令行跑，也没进 CI（CI 里没有真实向量）。
15. `docs/项目结构说明.md` 与 `docs/代码规范.md` 还没把 B3 新增模块
    （lease / usage / rate_limit / media_url / bm25_store / outbound_retry / insights）
    补进模块清单与分层依赖说明——按本项目的维护约定，这是一条 code review 检查项。

## 三、运维入口速查

| 要做什么 | 用什么 |
|---|---|
| 看现在能不能服务 | `GET /ready`（编排层摘流量用这个，不是 `/health`） |
| 看有什么要人处理 | `GET /api/v1/system/alerts` 或设置页「运行告警」 |
| 看花了多少钱 / 哪个模型在失败 | `GET /api/v1/system/usage`、「模型用量」卡、`GET /metrics` |
| 看业务效果 | `GET /api/v1/insights/dashboard` 或前端「运营看板」 |
| 看后台任务归谁在做 | `GET /api/v1/system/status` 的 `leases` |
| 备份 / 恢复演练 / 向量对账 | `scripts/backup_data.py` / `scripts/restore_data.py` / `scripts/verify_restore.py` |
| 端到端验证 | `scripts/ci_smoke.py`（自己起隔离实例，不碰本机 data/） |
| 迁移 | `alembic revision --autogenerate -m "..."` + `alembic upgrade head`（生产 `migrate_mode: alembic`） |

完整步骤与容量阈值见 [运维手册](运维手册.md)。
